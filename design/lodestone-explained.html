Path of Exile 2 · Lodestone

How Lodestone hunts for broken builds

Most build tools find the best version of a build people already play. Lodestone looks for the places where the game's maths breaks: two pieces that multiply instead of add, a stat that feeds damage without a ceiling, a condition that is always true against a boss.

It tests every skill against every condition, unique and keystone it can, keeps only what is far out of line, then builds each suspect for real with Whetstone, our build optimiser, and tries to explain it away.

What it looks for

Every broken build so far had one of these shapes

We sorted every broken build from PoE 2's patches 0.1 to 0.5 by why it broke. The common thread: something multiplies instead of adds. Lodestone is built around these ten shapes. The tag says whether Path of Building (PoB), the build calculator everything runs on, can work it out.

The hunt, in order

Seven steps from game data to a verdict

1

Read the text

Every gem, unique and passive is read for wording that has broken the game before: a "more" per unit, a count with no maximum, a cost that can reach zero, a trigger, "instead of". On patch day the scan compares the new text with the old and lists only what changed, because new content breaks first.

text_scan.py scan · text_scan.py diff OLD NEW
2

Build every skill, quickly

All 166 skills that can be a main skill get a quick build: crafted gear and the best supports, no passive tree. This is the same quick build Whetstone's search uses to compare candidates. It is done once for the whole game and again per ascendancy, with any class allowed to use any weapon.

From Whetstone: the gear crafting, support search and Path of Building calculations. Each recalculation takes about 20 ms, so a scan is hundreds of thousands of them.
3

Poke each build, one change at a time

Each probe changes one thing and measures damage against a pinnacle boss. A big jump on its own means little. What matters is a jump far bigger than the same change gives other skills.

Conditions

Each of the 56 enemy states PoB knows (Shocked, Frozen, Armour Broken, Poisoned...) switched on alone.

Unique and keystone matrix

Every unique (best rolls) and keystone worn alone on every skill. Weapon uniques go in the hand that holds them.

Stacks

Each piece tried again on top of a pile of one stat, because stacking pieces pay nothing until the stat is piled up.

synergy = D(piece+pile)·D(base) / (D(piece)·D(pile))
Scalers

One stat at 1x, 2x, 4x. Damage that grows faster than the stat is a red flag.

elasticity > 1
Pairs

Two pieces together against each alone.

synergy = (1+g(a+b)) / ((1+g(a))·(1+g(b)))
Combos

A setup skill puts the boss in a state, a payoff skill cashes it in. Scored as it plays: time to set up, then the window.

DPS = (T·setup + 12·payoff) / (T + 12)
4

Compare with the skill's own family

A crossbow unique that helps every crossbow skill is best-in-slot, not broken. So each gain is compared with skills of the same kind: same weapon for attacks, a shared damage type. Pieces strong on 6 or more skills go on a separate best-in-slot list. On one run this cut 141 flags to 17 one-skill interactions.

5

Build the suspect for real

A lead becomes two full Uber Endgame builds: one locked to the piece, one without it. Each is a complete Whetstone build with passive tree, gear, jewels, spirit and boss setup, and every damage source counted. Each side is built three times with the gear slots in a different order, because the same build can land up to about 2x apart on luck alone. The lead has to win in all three.

From Whetstone: the whole Uber Endgame stage, so the damage number is the same one a player's guide shows.
6

Try to explain it away

Most leads so far were our own mistakes, so this step comes before anyone hears about one.

Is it our model?

Does the number rest on something PoB doesn't limit, like a corpse a boss never leaves, a cast rate, or minions counted twice? If so, the model gets fixed and the lead dies.

Is it already known?

How many players on the poe.ninja ladder already run it. A known build is a rediscovery, not a find.

Outside evidence

Game data, the wiki, guides and forum posts. We can't test in game, so what none of these settles stays "PoB says, not confirmed".

Nerf risk

Bugs and extreme outliers get hotfixed in days; a multiplier usually lasts until the next patch.

Four real cases

How leads actually went

Lightning Conduit vs Shockedknown
  1. Condition scan: every skill gains about +20% against a Shocked enemy.
  2. Lightning Conduit gains +68%, far above the rest.
  3. That was a real broken build in patch 0.1, nerfed since.
Found blind, with no hint. It showed the detector's shape works.
Hexblast winning every searchfixed
  1. Hexblast topped search after search.
  2. Cause: PoB counted it cast back to back (2.1 casts a second), but it can only detonate a curse that is half expired: about once every 6 seconds per target.
  3. We added a usage limit for how often it can really go off. A saved Hexblast build fell from 4.34M to 352K.
Not a find. The model was wrong, and now every Hexblast score is fairer.
Leopold's Applause, penetration below 0dead
  1. Pair scan: +38%.
  2. Worn for real in place of the slot's item: +4%.
  3. Full builds, 3 orders each side: -1% best against best.
The early number stacked the unique on top of the slot's own item. Fixing that killed the lead.
Bonestorm Lich vs Comet Lichknown
  1. Search: Bonestorm well ahead.
  2. Fixed first: Bonestorm's release time (it can't fire every frame).
  3. Full builds: 10.5M vs 5.8M boss DPS, ahead in all 3 orders (+18%, +82%, +69%).
Real on our model, but about a third of Abyssal Liches on the ladder already play it.

Checking the checker

Does it find broken builds we already know about?

We loaded Path of Building as it was for patches 0.1 to 0.4, wrote down the broken builds each patch really had, and ran the scans blind. The bar, set before the run: find at least half, with at most one false alarm per real find.

2 of 11known broken builds foundBar: at least half.
~12false alarms per real find11 real against 129 false over 0.1-0.3. Bar: 1.
3 of 20ladder skills found blindpoe.ninja's 20 most played main skills, found in some ascendancy's top 5 without seeing the ladder (Nov 21).
up to ~2xbuild-to-build noiseThe same build with gear placed in a different order. Edges smaller than that are hard to see.

It failed the bar, so what Lodestone claims was narrowed the same day. The fixes since then have not been graded yet. A re-grade on the same answer key will show whether they help.

Limits

What it can and can't find

Kind of brokenCan Lodestone find it?
Multipliers stacking, penetration below 0, one stat scaling without limitYes, on its own. PoB calculates these exactly.
Trigger loops, free castsWith our own trigger-rate estimates. Rough.
Chain reactions, overlapping hitsLikely ones, with our own estimates.
Combos of 3 or more piecesSome, through wider overnight searches. It can't try everything.
Game bugsMostly no. It can only flag suspicious spots.
Brand-new mechanicsNot until PoB supports them.
Anything in gameNothing here is tested in game. Every number is Path of Building's model.
