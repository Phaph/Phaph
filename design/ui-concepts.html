Interface concepts · PoE 2 build optimizer

A workbench, not a chatbot

The app should feel like a craftsman's bench in Wraeclast: soot, brass and lamplight, with colour reserved for what the game itself colours (damage types, rarity). Every animation shows something real happening to the build. Nothing glows for the sake of it.

Concept 1

Each class has a living sigil

Picking a class changes the ambient motif behind the build header. It's generated on canvas from the class's own mechanics, so it never looks like stock art.

  • Shadow: vision cones sweep across smoke. Step "outside" them on hover, like Stealth.
  • Low motion: 20-60 slow particles, under 30% opacity, paused off-screen and for reduced-motion users.
  • The motif reacts once at key moments: a pulse when the build finishes, a flare on a new best.

Concept 2

The loading screen is the work

A guide takes about a minute and a half. Instead of a spinner, the page streams the optimiser's real trace: notables light up as they're allocated and the DPS figure climbs.

  • Shown here: the actual allocation order and DPS from our Tempest Flurry Invoker mid maps run.
  • Engine side: the tree step list already exists. It just needs streaming over the job endpoint.
  • Players learn why a node was taken, which builds trust in the result.
Concept 3

Gear stamps in like a crafting bench

Each affix lands in priority order with a short heat flash, the way a crafted mod appears. The diamond pips show the affix tier the budget allows.

  • Switch stages to watch the same helmet slot upgrade from leveling to endgame. These are the engine's real picks.
  • Each line links to a trade search with that stat as the minimum.
  • Priority order is the point: the first line is what to buy first.

Concept 4

Damage has a colour

The interface's only bright colours are damage types: physical, fire, cold, lightning, chaos. Every DPS bar is split by type, so a player sees at a glance what a build scales.

  • Mapping and bossing are one toggle: same gear, a support gem swap.
  • Brass is the only interface accent: selection, focus, winners.
  • Example split for illustration. The engine can report the real per-type numbers.
Concept 5

Compare as a duel

Up to three builds side by side, one metric at a time. Bars race out together and the leader takes the brass. Pros and cons sit under each name.

  • Numbers here are our real 5 divine comparison: all three builds fully crafted at the same budget.
  • One metric per view keeps it readable on a phone.

Concept 6

Budget first, as a ladder

The first question the app asks. Five rungs, each a growing stack of coins rather than a dropdown, so nobody gets shown a 2,000 divine build by accident.

Style sheet

Palette, type and motion rules

Type

  • IM Fell English SC for display: old engraved print, grim without copying the game's own font.
  • Manrope for reading, JetBrains Mono for every number and stat line.
  • Stats are always monospaced and tabular, so columns line up.

Motion

  • One easing curve everywhere, 300-900ms.
  • Motion only for real events: an allocation, an affix, a finished build.
  • No floating orbs, no gradient blobs, no typing-cursor "AI" effects.

Avoid

  • Purple-blue gradients and glowing neon cards.
  • Chat bubbles: the prompt is a single forge-like input, and the answer is a build sheet.
  • Any GGG art, logos or item renders.
